# Разработка MemeHive

[English](development.md) | **Русский**

[К README](../README.ru.md) · [Архитектура](architecture.ru.md)

MemeHive — Android-приложение на Kotlin с одним Gradle-модулем `app`. Интерфейс построен на Jetpack Compose и Material 3; Room хранит метаданные, Coil отображает изображения.

## Подготовка

1. Клонируйте репозиторий и откройте его корневую папку в Android Studio.
2. Установите Android SDK Platform **37** — compile SDK, указанный в `app/build.gradle.kts`.
3. Используйте **JDK 21** для запуска Gradle. В репозитории заданы требования к демону Gradle с JetBrains JDK 21; CI настраивает Java 21. Целевая версия байткода Java/Kotlin отдельно задана как JVM 11.
4. Позвольте Android Studio указать путь к SDK в локальном `local.properties`, затем синхронизируйте Gradle. Не добавляйте машинозависимые пути к SDK в репозиторий.
5. Выберите эмулятор или устройство с Android 10 / API 29 или новее и запустите конфигурацию `app`.

Используйте версию Android Studio, совместимую с Android Gradle Plugin проекта. Версии зависимостей и плагинов заданы в [`gradle/libs.versions.toml`](../gradle/libs.versions.toml), а версия Gradle закреплена в [`gradle-wrapper.properties`](../gradle/wrapper/gradle-wrapper.properties). Запускайте Gradle через wrapper из репозитория.

Проект использует target API 36 и compile API 37. Первая настройка требует доступа к репозиториям зависимостей и загрузкам инструментов. Учётные данные для серверной части не нужны.

### Сборка и установка из терминала

В корне репозитория выполните:

```sh
./gradlew assembleDebug
./gradlew installDebug
```

Для `installDebug` нужен запущенный эмулятор или устройство с отладкой по USB. Отладочный APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`. В Windows используйте `gradlew.bat` вместо `./gradlew`.

```sh
./gradlew assembleRelease
```

В конфигурации релизной сборки не задан ключ подписи. Сборка релизного APK, его подписание и распространение — отдельные этапы. Минификация релизной сборки отключена.

## Проверки

Проверки CI, не требующие устройства:

```sh
./gradlew testDebugUnitTest lintDebug assembleRelease assembleDebugAndroidTest
```

Инструментальные тесты на подключённом устройстве или эмуляторе:

```sh
./gradlew connectedDebugAndroidTest
```

Workflow в [`.github/workflows`](../.github/workflows) запускает тесты на эмуляторе API 35 x86_64. Команда `assembleDebugAndroidTest` только собирает тестовый APK; `connectedDebugAndroidTest` запускает тесты.

| Каталог тестов | Что проверяется |
| --- | --- |
| `app/src/test` | Ранжирование поиска, проверка архивов, очистка файлов, преобразования моделей, состояние и вспомогательная логика сообщений |
| `app/src/androidTest` | Работа Room и миграций, сохранение и перенос коллекций, доступ к изображениям, взаимодействия Compose, восстановление activity и черновиков |

Отчёты создаются в `app/build/reports/`; отчёты тестов на устройстве — в `app/build/reports/androidTests/`.

## Работа с кодом

Основной Kotlin-код находится в `app/src/main/java/com/farywave/memehive/`. О структуре пакетов и потоках данных см. [Архитектура](architecture.ru.md).

- Размещайте отображение интерфейса в Compose-экранах, состояние и обработку действий — во ViewModel, согласованные изменения данных — в use cases.
- UI обращается к репозиториям только через use cases, как для чтения, так и для записи. Это относится и к ViewModel, и к activity.
- Репозитории не должны зависеть друг от друга. Координируйте операции с несколькими репозиториями в use cases. Эти [правила зависимостей](architecture.ru.md#правила-зависимостей-и-их-назначение) предотвращают циклические зависимости и задают единый способ доступа к бизнес-логике.
- Собирайте зависимости в `AppContainer`.
- Добавляйте пользовательские строки в `app/src/main/res/values/strings.xml` и обновляйте русский перевод в `values-ru/strings.xml`.
- При изменении изображений используйте существующие механизмы сохранения и очистки файлов.
- Выбирайте тесты под изменяемое поведение. Работа базы данных, Android URI и Compose обычно требует инструментальных тестов.

### Изменения базы данных

Снимки схемы Room хранятся в репозитории в `app/schemas/`. При изменении схемы:

1. Увеличьте версию базы, реализуйте миграцию и зарегистрируйте её в `MemeHiveDatabase`.
2. Выполните сборку для генерации новой схемы.
3. Добавьте или обновите тесты миграций и запустите их на устройстве или эмуляторе.
4. Включите сгенерированную схему в коммит вместе с миграцией.

CI проверяет, что после сборки нет изменённых или неотслеживаемых файлов схемы. Не заменяйте миграции пересозданием базы с удалением пользовательской библиотеки.
